# UI Locale 行为规范（i18n spec）

本规范描述界面语言（Locale）的唯一所有权、解析顺序、持久化与回退规则。修改 locale 相关代码前先更新本文件。

## 支持的语言与命名

- 受支持 Locale：`zh-CN`、`en-US`、`pt-BR`（展示名分别为 `中文简体`、`English`、`Português - BR`）。
- 类型所有权：`packages/shared/src/protocol.ts` 的 `Locale` / `LocalePreference` 是 UI 侧唯一契约；CLI 侧使用 `apps/zcode-cli/packages/contracts` 的 `SupportedLocale` / `UiLocale` 与 `shared-types` 的 `GlobalLocale`。新增语言时四处必须同步，否则 CLI typecheck / schema 校验会失败（这是有意的防呆）。

## 偏好解析顺序（UI）

1. `initialLocale`（窗口启动参数，desktop 传入）；
2. `localStorage["zcode-locale-preference"]`（`"system"` 或具体 Locale）；
3. `setting.json` 的 `locale` / `localePreference`（远控场景 `preferSettingServiceLocale` 时以桌面为准）；
4. 兜底 `"system"`。

`"system"` 的解析归属：

- Desktop：main 进程 `resolveSystemApplicationLocale()`（`getPreferredSystemLanguages` → `getLocale`）。main 不能导入 `@zcode/ui`，所以这里保留一份防御性副本（`zh*→zh-CN`、`pt*→pt-BR`、其余 `en-US`）；**新增语言时必须与 `systemLocale.ts` 同步修改**，否则主进程与界面语言会不一致。
- Web/CLI：navigator/env 语言标签 → `zh*→zh-CN`、`pt*→pt-BR`、其余 `en-US`。

语言标签 → Locale 的映射在 UI 侧唯一实现在 `packages/ui/src/i18n/systemLocale.ts`（`resolveNavigatorLocaleTag`）；CLI 侧 `normalizeLocale` 同步。persisted 偏好读取统一走 `readStoredLocalePreference()`（key：`zcode-locale-preference`），不要在调用点手写 key 或裸读 `localStorage`。

## 状态与事件

- IntlProvider 是 locale 运行态唯一 owner；切换走 `setLocalePreference`：
  本地 state → `localStorage` → 跨窗口广播（`state:locale`，带 preference + resolvedLocale）→ `settingService.update` 异步落盘（失败不阻塞 UI，下次切换重试）。
- 消费端（Settings 下拉、sidebar 菜单、cycle 按钮）的值白名单必须覆盖全部 Locale；遗漏会导致选项点击被静默丢弃。

## 持久化校验

- Desktop `setting.json`：`packages/shared/src/validationAppSettings.ts` 的 `localeSchema` / `localePreferenceSchema`；
- CLI 配置文件：`apps/zcode-cli/packages/adapters/src/config/schema.ts` 的 `uiSchema.locale`。
  两处 enum 漏掉新 Locale 时，CLI 会把整份配置判为无效并静默丢弃，属于高危回归。

## 外部资源回退（只有中英两份文案的服务）

规则：`zh-CN → 中文渠道；其余界面语言（含 pt-BR）→ 英文渠道`。适用：

- 社区入口：`getCommunityUrlFromConfigs`（desktop 直接调用）；web 侧读取 helpConfig 的两 key 映射时同样归一化；
- 更新日志：`getLocalizedUpdateReleaseNotes`（zh 退顶层默认；非 zh 先退 en-US 条目再按旧链条）；
- 分享错误标签 / 分隔符：`conversationShareError.ts`（`locale === "zh-CN" ? zh : en`，禁止“非 en 即 zh”）；
- Coding Plan webview、provider 模板名、分享落地页：调用点显式归一化为 `zh-CN | en-US`。

## 地区约定

- 周起始日（任务时间线分组）：zh 周一；en 与 pt-BR（巴西历法）周日。

## 验收场景（改动 locale 行为时必须覆盖）

1. Windows 系统语言为 pt-BR 的机器上，`pnpm dev:desktop` 首帧即为葡萄牙语；
2. Settings 下拉与 sidebar 菜单选择 `Português - BR` 立即生效，且刷新后保持；
3. CLI `zcode --locale pt-BR` / `/locale pt-BR` 后重启，既有配置（权限、MCP、模型）完整保留；
4. pt-BR 界面下：社区入口可用（英文渠道）、更新日志不出现中文、分享错误文案不出现中文；
5. `pnpm typecheck`（根）与 `pnpm --dir apps/zcode-cli typecheck` 均通过；`scripts/i18n-assemble.mjs` 校验 key/placeholder 双侧一致。

## 翻译目录维护

- UI 目录：`packages/ui/src/i18n/locales/`（key 必须与 en-US 完全一致）；
- 工具：`scripts/i18n-split.mjs` 拆分 en-US → `.i18n-chunks/source/chunk-*.json`；`scripts/i18n-assemble.mjs` 合并 `.i18n-chunks/pt-BR/` 并做 key/placeholder/空值校验后生成目标文件。
